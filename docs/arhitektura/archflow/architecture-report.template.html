Executive summary

Two runtimes, one state layer

System character

The repository is organised around two independent runtimes that share the same storage. A Flask service owns the telemetry plane: an APScheduler job runs every hour, pulls the official ARSO XML feed, parses stations and measurements, merges them into a station-keyed payload, writes the hot copy to Redis, upserts the relational rows into PostgreSQL, and rebuilds four history payloads. The Next.js dashboard is a static export behind nginx and reads that data through two REST endpoints.

The second runtime is a LangGraph question-answering graph. A router classifies each question into rag, sql, redis, or splosno; one of four source nodes gathers evidence from pgvector, PostgreSQL, or the Redis cache; and an answer node composes a grounded Slovenian response through the DeepSeek API. Document ingestion is a separate, watcher-driven indexing path that chunks PDFs and text files and embeds them into pgvector through Ollama.

The state layer is the contract between the two planes: measurements for the dashboard, measurements plus document vectors for the agent.

Open seam
The AI plane stops at the CLI. Flask exposes /api/latest, /api/history, and /api/status — but no question endpoint. Nginx already reserves a slow-lane proxy for /api/(vprasanje|rag|agent|ask|query). Wiring the LangGraph graph into that route is the single highest-leverage integration step.

03 · Data flow

Two request lifecycles

The left column is the hourly write path that keeps the dashboard fresh. The right column is the on-demand read path that turns a question into an answer.

Telemetry plane

Hourly · Flask

Write path: ARSO XML → Redis hot copy → PostgreSQL history → REST payloads.

01
Scheduler fires

BackgroundScheduler runs update_data() every hour inside an app context; one synchronous run also happens at boot.

02
Fetch the feed

fetch_arso_xml() requests the ARSO hourly XML with a 10 s timeout and UTF-8 decoding.

03
Parse twice, merge once

Station and measurement parsers each return a ParseResult; the merger keys everything by station_id and appends measurements.

04
Cache before persist

The merged snapshot is serialised to latest_merged_data first, so the API can recover even if the DB insert fails.

05
Upsert and rebuild

insert_all_data() writes stations, pollutants, and measurements; refresh_history_cache() rebuilds all four history periods.

06
Serve

/api/latest returns the cached JSON; /api/history validates the period, rate-limits per IP, aggregates into time bins, and attaches EU/WHO AQI scores.

Question plane

On demand · LangGraph

Read path: question → route → evidence → grounded answer.

01
CLI entry

python -m ai.main "<vprašanje>" builds the graph and seeds AgentState with question, empty route/context/answer, and a null error.

02
Classify

router_node prompts DeepSeek at temperature 0 and validates the response against four routes, with keyword fallbacks if the model rambles.

03
Dispatch

A conditional edge maps state["route"] to rag, sql, redis, or splosno — all four converge on the answer node.

04
Gather evidence

RAG embeds the query through Ollama and runs cosine search in pgvector; SQL asks DeepSeek for a query and executes it with a read-only role; Redis extracts a period and reads cached keys.

05
Compose

answer_node selects a with-context or without-context prompt, calls DeepSeek at temperature 0.3, and refuses to invent data outside the context.

06
Return

The graph reaches END and the CLI prints route, error, and answer. Errors are converted into a readable Slovenian data-fetch message.

Shared contract:  PostgreSQL holds measurements and document vectors · Redis holds the latest snapshot and precomputed history payloads · both paths use the same database.
04 · State layer

Five tables, two hot keys

PostgreSQL 17 with pgvector is the durable source of truth. Redis exists to keep the dashboard response path short and to give the agent a cache-backed route for current readings.

stations RELATIONAL

  • id · integer PK
  • station_id · source code
  • station_name · display name
  • latitude / longitude
  • d96_easting / northing
  • elevation_meters

Measurement FK cascades on delete.

pollutants LOOKUP

  • id · integer PK
  • name · unique (co, o3, no2…)
  • unit · μg/m³, CO in mg/m³

Seeded dynamically from the measurement dataclass fields.

measurements FACT

  • id · integer PK
  • station_id → stations.id
  • pollutant_id → pollutants.id
  • value · float, nullable
  • measured_at · datetime

Indexed for latest-row and period queries.

documents VECTOR

  • content · chunk text
  • embedding · pgvector
  • source · file name
  • UNIQUE (source, content)

Cosine distance via <=>; top-k retrieval.

rag_sources_status REGISTRY

  • source · unique file
  • status · processing/done/failed
  • content_hash · SHA-256
  • chunks_count · integer
  • processed_at · timestamp
  • last_error · text

Unchanged files are skipped by hash.

Redis HOT PATH

  • latest_merged_data
  • history_payload:day
  • history_payload:week
  • history_payload:month
  • history_payload:year

Values are JSON strings, UTF-8 encoded.

ingestion invariants
skip   if status = done and sha256(file) unchanged
reset  delete rows and re-index when the hash changes
claim  status = processing before any embedding call
guard  expected_chunks == actual_rows, else fail
mark   status = failed + last_error on any exception
chunk  1500 chars, 200 overlap, RecursiveChunker

Latest-snapshot fallback ladder

1 Redis latest_merged_data
2 Flask-Caching cache backend
3 In-process _LATEST_MERGED_DATA_JSON
4 Force update_data() and retry
5 Rebuild payload from PostgreSQL
05 · Agent routing

One router, four evidence paths

The router is a prompt, not a classifier model. It returns a single token and the graph trusts the state field after sanitising it. Each branch reaches a different tool with a different grounding contract.

ragDocuments
Law, definitions, reports, limit values. The node calls rag_search(question, top_k=5). The tool embeds the query through Ollama (nomic-embed-text) and orders documents by cosine distance. Context is a JSON wrapper of question + chunks with similarity.
rag.py
pgvector · top 5
sqlHistory
Past measurements, averages, maxima, station comparisons. The node asks DeepSeek to write a SELECT against the three-table schema, strips markdown fences, and executes through sql_query. Guardrails: read-only DB role, SELECT-only check, forbidden DML keywords, single statement, forced LIMIT 100.
sql.py
PostgreSQL · read-only
redisCurrent
Now, last 24 h, this week, this month, this year. A second prompt extracts one of latest | day | week | month | year; the node reads latest_merged_data or history_payload:<period>.
redis.py
Redis · cached JSON
splosnoFallback
Greetings and off-topic questions. The node returns empty context; the answer node switches to the without-context prompt and responds politely in Slovenian without pretending to have data.
splosno.py
no tools
Legacy path

ai/agent.py still contains a second agent runtime

A standalone ReAct-style loop binds the same four tools to DeepSeek and iterates up to 15 times, appending tool messages until the model stops calling tools. The LangGraph graph never imports it. Keeping both is useful for experimentation, but the prompts and tool contracts can drift.

07 · Delivery pipeline

From main to Hetzner

Every push to main runs the test suite, builds a container and a static bundle, ships both to the server, and verifies the public endpoints before declaring success.

01

Push to main

GitHub Actions checks out the repository with Node 24 forced for JavaScript actions.

02

Test with uv

uv sync --locked --all-extras then uv run pytest; a failing test stops the deploy.

03

Build and push the API image

Buildx caches through GHCR and pushes ghcr.io/miranas/air_pollution_app:latest.

04

Build the static frontend

npm ci && npm run build produces frontend-next/out because next.config.ts sets output: 'export'.

05

Copy assets to the server

The out/ directory and compose/nginx/Prometheus configs are SCP'd to /opt/air_pollution_app.

06

Recreate the stack

Compose pulls the new backend image and force-recreates backend, redis, and nginx.

07

Verify before finishing

/api/status must return project JSON, / must serve the HTML shell, and /api/latest is retried five times for HTTP 200.

Check before the next deploy: the workflow builds docker/Dockerfile.api, but the repository currently contains docker/Dockerfile. Either rename the file or update the workflow path, or the image build step will fail.
08 · Architecture insights

What the code actually reveals

Seven findings that are not obvious from the directory tree — integration seams, duplicated logic, and safety mechanisms worth preserving.

01

The AI plane is complete but unreachable from the web

The LangGraph graph, router, four source nodes, and answer composer all work from ai/main.py. Flask registers exactly one blueprint — api_latest — with /api/latest and /api/history. Nginx already routes /api/(vprasanje|rag|agent|ask|query) to a 300-second slow lane, so the intended integration point exists at the edge but has no server-side handler.

How to apply: add a Flask /api/ask blueprint that calls graph.invoke(), disable proxy buffering (already done), and map state["answer"] / state["error"] into the response.

Filesbackend/app.py
backend/routes/api_latest.py
docker/nginx.conf
ImpactHigh
02

Two agent runtimes coexist

ai/graph.py is the structured five-node graph. ai/agent.py is an older 15-iteration tool-calling loop with the same four tools. Only the graph is documented in the current plan, but both remain runnable.

03

SQL safety is three walls deep

A separate read-only database user, a SELECT-only keyword guard that rejects DML and multi-statement input, and an automatic LIMIT 100 when the model forgets one.

04

The cache is a ladder, not a layer

/api/latest falls through Redis → Flask-Caching → an in-process global → a forced update_data() → a direct PostgreSQL rebuild. Each rung exists to survive a different failure mode.

05

Document indexing is idempotent by hash

Each source file is claimed as processing, hashed with SHA-256, chunked, embedded, and verified by comparing expected chunks to inserted rows. Unchanged files cost one hash read.

06

AQI math exists twice

backend/utils/history_cache.py scores EU/WHO bands in Python; frontend-next/app/utils/aqi.ts reimplements the same thresholds in TypeScript. Two implementations means two places to drift.

07

History is pre-shaped for charts

Periods are aggregated into 1 h, 3 h, 6 h, and 24 h buckets and downsampled to 192 / 336 / 360 / 365 points, so the browser never receives raw hourly rows for a year.
